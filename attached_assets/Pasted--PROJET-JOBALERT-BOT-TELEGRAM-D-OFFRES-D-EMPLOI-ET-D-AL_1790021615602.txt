# 🚀 PROJET : JOBALERT — BOT TELEGRAM D'OFFRES D'EMPLOI ET D'ALTERNANCE

Je veux créer une véritable application Telegram Bot appelée **JobAlert**.

Le principe est similaire à un bot Telegram qui envoie automatiquement des logements CROUS : l'utilisateur configure ses critères une seule fois et reçoit ensuite directement dans Telegram les nouvelles offres correspondant à sa recherche.

L'objectif principal est de créer un bot :

* ⚡ très rapide
* 🤖 automatisé
* 🌍 européen
* 🔎 capable d'agréger de nombreuses sources
* 🧹 capable de supprimer les doublons
* 🎯 capable de filtrer les offres selon les critères de chaque utilisateur
* 📩 capable d'envoyer immédiatement les nouvelles offres
* 🛠️ facilement extensible à de nouveaux pays et sites
* 🔐 sécurisé
* 💰 sans dépendance obligatoire à une API IA payante

---

# 1. CONCEPT PRINCIPAL

L'utilisateur ouvre le bot Telegram et écrit :

`/start`

Le bot lui demande progressivement :

1. 💼 son secteur / métier
2. 📋 son type d'emploi
3. 🌍 les pays dans lesquels chercher
4. 📍 éventuellement les villes/régions
5. 🎓 son niveau d'études
6. 💰 éventuellement un salaire minimum
7. 🏠 éventuellement le télétravail
8. 🗣️ éventuellement les langues
9. 🔔 la fréquence des alertes

Une fois terminé, le bot sauvegarde les préférences.

Ensuite, les workers recherchent régulièrement les nouvelles offres.

Lorsqu'une offre correspond :

→ elle est envoyée immédiatement sur Telegram.

---

# 2. PRIORITÉ ABSOLUE : RAPIDITÉ

C'est une exigence essentielle du projet.

Je ne veux PAS que l'utilisateur attende 20 secondes après avoir appuyé sur un bouton.

Toutes les interactions Telegram doivent être rapides.

Exemple :

Utilisateur :

`/preferences`

Le bot doit répondre immédiatement.

Il ne doit PAS faire :

```python
await search_all_websites()
await analyse_all_jobs()
await send_results()
```

avant de répondre.

Utiliser une architecture asynchrone.

Architecture :

```text
                   TELEGRAM
                       │
                       ▼
              ┌─────────────────┐
              │ Telegram Handler│
              └────────┬────────┘
                       │
                Réponse immédiate
                       │
                       ▼
              ┌─────────────────┐
              │ PostgreSQL      │
              └─────────────────┘


En parallèle :

Sources
   │
   ├── France Travail
   ├── EURES
   ├── ADEM
   ├── Forem
   ├── Bundesagentur
   ├── jobs.ch
   ├── etc.
   │
   ▼
Normalisation
   │
   ▼
Déduplication
   │
   ▼
Matching
   │
   ▼
Notification Telegram
```

Les recherches doivent fonctionner en arrière-plan.

Si une source est lente, elle ne doit jamais bloquer les autres.

Utiliser :

* asyncio
* tâches concurrentes
* httpx/aiohttp
* timeouts
* retry avec exponential backoff
* connection pooling
* cache
* ETag / Last-Modified lorsque disponible

# 26. RÈGLE FONDAMENTALE POUR LES SOURCES

Avant d'utiliser un site :

1. rechercher une API officielle ;
2. rechercher un flux RSS/Atom ;
3. rechercher une source open data ;
4. vérifier les conditions d'utilisation ;
5. vérifier si l'automatisation est autorisée ;
6. utiliser ensuite une page publique uniquement si cela est permis.

NE PAS contourner :

* CAPTCHA
* Cloudflare
* authentification
* anti-bot
* paywall
* protections techniques
* restrictions contractuelles.

NE PAS inventer une API.

Si une source ne peut pas être automatisée proprement :

```text
🟡 Source non connectée
```

et continuer avec les autres.

2. URL canonique
3. domaine + ID
4. entreprise
5. titre
6. ville
7. date
8. similarité des données

Conserver éventuellement les différentes sources associées.

Mais n'envoyer qu'une notification.

# 42. IA

L'IA est OPTIONNELLE.

Ne pas rendre le projet dépendant d'OpenAI ou d'une autre API payante.

Utiliser l'IA seulement pour des tâches où elle apporte réellement quelque chose :

* matching sémantique avancé
* traduction
* compréhension d'un titre ambigu
* classification complexe
* extraction d'informations
* analyse d'une description

Architecture :

```text
OFFRE
 ↓
FILTRAGE RAPIDE
 ↓
Correspondance évidente ?
 ├── OUI → Telegram immédiatement
 │
 └── INCERTAIN
       ↓
     IA optionnelle
       ↓
     Telegram
```

Ainsi une offre évidente ne doit pas attendre une API IA.

# 55. CONTRAINTE REPLIT

Le projet doit être conçu pour pouvoir commencer avec le plan gratuit de Replit.

Éviter les services payants inutiles.

Ne pas utiliser une API IA payante pour le fonctionnement de base.

Ne pas dépendre d'un service externe coûteux pour la recherche.

Utiliser les services intégrés à Replit lorsque cela est pertinent.

Le projet doit pouvoir évoluer vers une infrastructure plus importante si le nombre d'utilisateurs augmente.

IMPORTANT :

Ne pas supposer que le plan gratuit peut exécuter un nombre illimité de workers simultanément.

Prévoir une architecture où les workers peuvent être regroupés et où la fréquence de recherche est configurable.

Si une limite du plan Replit empêche une fonctionnalité :

→ me l'indiquer clairement
→ proposer une architecture compatible avec la limite
→ ne pas créer une fausse fonctionnalité.
